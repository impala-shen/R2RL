Replay and Reinforce RL (R²RL)

Real-world reinforcement learning for UR robot manipulation, built with PyTorch, skrl, Gymnasium, and UR RTDE. The policy produces Cartesian pose increments; a robot environment executes them and returns measured observations, rewards, and episode-end signals.

The main entry point is task_R2RL.py. The algorithm retains the historical names OSRL, OSRL_CFG, and algorithms/OneShot/; its output directory also retains osrl. This README describes the current real-robot code and its configured values, rather than a verified paper reproduction.

The online execution flow is:

SequentialTrainer -> agent.act() -> environment.step(action)
                                      -> RTDE -> UR controller -> robot
                                      <- measured pose and force/torque
                  <- observation, reward, terminated, truncated, info
                  -> record transition -> replay memory -> learning update

Gymnasium defines reset(), step(), observation_space, and action_space. skrl’s wrap_env() adapts the environment for the trainer. RTDE is the hardware communication layer; the UR controller executes the commanded motion.

Task settings

All online entry points select tasks through task_settings.py. Choose snapfit, peginhole, assembly, or openbox using --task, or change the script’s DEFAULT_TASK variable. The selected preset supplies the environment class, home pose, observation dimension, episode limit, and default demonstration path. Log directories follow the selected task name.

python task_R2RL.py --task snapfit
python task_R2RL.py --task peginhole
python task_R2RL.py --task assembly
python task_R2RL.py --task openbox --demo-file path/to/openbox_demo.csv
Shared option Setting
--task Task preset; defaults are set with DEFAULT_TASK in each entry point
--robot-ip Robot address; default 192.168.1.11
--home-pose X Y Z RX RY RZ Override the selected task’s home pose
--max-steps Override the episode limit; all presets default to 100
--demo-file Override the selected task’s demonstration CSV

Edit TASKS in task_settings.py to change the defaults for a fixture. Home poses were copied from the existing robot scripts, including the previous peg-in-hole example. A pose is [x, y, z, rx, ry, rz]: translation in meters and orientation as a rotation vector in radians. Home poses and environment reset waypoints remain specific to the physical setup. Reset routines move the robot, clear episode history, and zero the force/torque sensor.

The registry selects snap-fit data for snap-fit, peg-in-hole data for peg-in-hole, and PegInHole/assembly.csv for assembly. No open-box demonstration is included, so supply --demo-file for demonstration-based training on that task. Dimension and nonempty-file checks run before connecting the robot; matching dimensions alone do not establish that a demonstration matches the physical task or action convention.

The default training budgets are 5,000 environment steps for R²RL, 10,000 for IBRL, and 10,000 for Residual RL. Residual RL supports --timesteps. R²RL and IBRL express their budgets as multiples of the configured episode limit.

Observations and actions

All robot environments accept six normalized actions in [-1, 1]. _denorm() converts them to pose increments using ACTION_MIN and ACTION_MAX:

delta_pose = (action + 1) / 2 * (ACTION_MAX - ACTION_MIN + 1e-8) + ACTION_MIN
Environment Observation size Contents Active action interpretation
Snap-fit 19 Relative TCP pose (6), wrench (6), accumulated X force (1), previous action (6) Direct addition to current base-frame pose
Open-box 19 Same layout as snap-fit Direct addition to current base-frame pose
Peg-in-hole 18 Relative TCP pose (6), wrench (6), previous action (6) Direct addition to current base-frame pose
Assembly 18 Same layout as peg-in-hole Tool-relative increment through command_in_tcp_frame()

Environment observations are clipped and normalized with the OBS_LOW/OBS_HIGH arrays in each _get_obs(). Relative translation is current_xyz - home_xyz; relative orientation uses R_home.inv() * R_current. Previous actions remain in normalized units. Demonstrations must match these units, ordering, and action conventions.

Physical action bounds, in [dx, dy, dz, drx, dry, drz] order:

Tasks ACTION_MIN ACTION_MAX
Snap-fit / open-box [-0.001, -0.0005, -0.0003, -0.01, -0.01, -0.01] [0.001, 0.0005, 0.0007, 0.01, 0.01, 0.01]
Peg-in-hole / assembly [-0.000529, -0.000375, -0.001301, -0.001067, -0.000417, -0.00127] [0.000529, 0.000375, 0.000051, 0.001067, 0.000417, 0.00127]

Translation bounds are meters; rotation bounds are radians. Because Z bounds are asymmetric, a normalized zero action does not correspond to zero Z displacement.

Assembly remaps translation to [-dy, -dx, -dz] and rotation to [-drx, dry, drz], with both helper scales set to 1. It computes T_target = T_current @ T_rotation @ T_translation, then sends the absolute base-frame target. The other environments add rotation-vector components directly as well as positions; this is not general incremental rotation composition. Snap-fit also calculates a tool-frame target, but the active command uses direct pose addition.

All four step() methods use moveL with speed 0.3 m/s and acceleration 0.3 m/s². The speed/servo alternatives are commented out. CTRL_HZ = 20 is declared, but the loop sleep is commented out; step duration depends on motion completion and processing.

Rewards and episode endings

The current rewards use measured robot signals:

Task Nonzero reward condition and value
Snap-fit If 100 < accumulated_Fx < 2000 and Fx > 5 N, reward is 1 - min(0.02, abs(z - target_z)) / 0.02; target_z = home_z + 0.02
Open-box If 100 < accumulated_Fx < 10000, Fx > 3 N, and dist < height - 0.002, reward is 1 - dist / height; dist = clip(target_z - z, 0, height)
Peg-in-hole Reward 1 when absolute base-frame z < 0.098 m, otherwise 0
Assembly Reward 1 when absolute base-frame y < -0.004 m and abs(Fx) > 5 N; reward 0.3 when y < -0.001 m and abs(Fx) > 5 N; otherwise 0

Accumulated X force is a sum of force samples, not a time-integrated force. Tune reward thresholds and normalization for the actual fixture.

Task Total force limit Additional termination conditions
Snap-fit 90 N abs(Fx) > 50, abs(Fy) > 30, abs(Fz) > 50, or Fx < -20 N
Open-box 100 N abs(Fx) > 60, abs(Fy) > 30, abs(Fz) > 50, Fx < -20 N, or z > target_z + 0.05 m
Peg-in-hole 100 N abs(Fx) > 30, abs(Fy) > 30, or abs(Fz) > 50 N
Assembly 100 N abs(Fx) > 40, abs(Fy) > 15, or abs(Fz) > 15 N

At the configured episode limit, step() reports truncation unless another termination condition is reached. Reward attainment does not itself terminate the episode. Peg-in-hole and assembly calculate range_limit_reach, but do not include it in the termination return. Python force checks happen after the motion command returns.

Task presets use absolute paths under data/demonstrations/. The selected file is passed to the agent through cfg.demo_file, and expert replay capacity follows its row count. Online environment construction does not read demonstration CSVs; R²RL policy evaluation therefore does not require one. IBRL still requires demonstrations for its existing imitation/RL selection setup, and a Residual RL one-demo base requires its action sequence during training and evaluation.

For recorded-observation mode, an environment loads its task preset CSV or an explicit constructor demo_file. Open-box requires that explicit path because no dataset is included.

offline_mode=True on a robot environment is not a hardware-free training mode: it selects recorded observations, while reset and motion code still use hardware. Use the dedicated OfflineTrainer for updates without rollouts.

R²RL and IBRL configure Gaussian exploration standard deviation 0.1, a linear multiplier max(1 - timestep / timesteps, 0.01), target smoothing standard deviation 0.2, and smoothing clip 0.5. These noise settings apply only in the algorithm branches that use them; both default to stochastic actors. Residual RL configures explicit exploration noise only for deterministic policies: standard deviation 0.01 and multiplier floor 0.05. Deterministic Bellman updates additionally use smoothing standard deviation 0.02 and clip 0.05.

Actor and critic hidden layers are generally 256 -> 128 -> 64 with ReLU; the R²RL/IBRL value network uses ELU. Stochastic actors output mean and log-standard-deviation heads with log-standard-deviation bounds [-5, 1]. The deterministic Residual RL output head starts at zero; all residual policies execute a zero residual during the initial 100-step base-only phase.

Residual RL supports independent --q-method {bellman,iql}, --policy-method {maxQ,DDPG+BC}, and --deterministic-policy / --no-deterministic-policy choices. Its DDPG+BC settings are ddpg_bc_alpha=1 and bc_loss_scale=1.0. A checkpoint base receives raw environment observations by default (preprocess_base_observations=False).

Residual RL enables RunningStandardScaler for agent observations. R²RL and IBRL currently assign cfg.observation_preprocessor_preprocessor, whereas the agent reads cfg.observation_preprocessor; the extra-suffix assignment does not enable that observation preprocessor. Their state preprocessor is configured separately. Environment normalization still runs.

BC’s configured values are 7,500 expert-memory slots, batch size 64, two gradient steps per update, learning rate 3e-4, seed 43, and 10,000 offline trainer iterations. The entry point is unfinished and is not part of the runnable online task selector.

Training and evaluation

Configure the task preset and physical fixture, then choose the method. Supply checkpoints explicitly for the selected task; no trained checkpoints are included. R²RL starts from scratch when --checkpoint is omitted. A provided checkpoint warm-starts training or supplies the policy for evaluation.

# R²RL training and warm start.
python task_R2RL.py --task snapfit
python task_R2RL.py --task snapfit --checkpoint path/to/agent.pt

# Evaluate the policy mean; --stochastic-evaluation enables sampling.
python task_R2RL.py --task snapfit --eval --checkpoint path/to/agent.pt --eval-episodes 30

# IBRL requires a compatible frozen imitation policy.
python task_IBRL.py --task assembly --bc-checkpoint path/to/assembly_bc.pt

# Residual training with the selected task's demonstration base.
python task_ResidualRL.py --task snapfit --base-policy-type one_demo --timesteps 10000

# Open-box requires a task-specific demonstration supplied by the user.
python task_ResidualRL.py --task openbox --base-policy-type one_demo --demo-file path/to/openbox_demo.csv

# Residual training with a frozen stochastic base policy.
python task_ResidualRL.py --task snapfit --base-policy-type checkpoint --base-checkpoint path/to/base_agent.pt

# Evaluate with the same task/base configuration used during training.
python task_ResidualRL.py --task snapfit --eval --checkpoint path/to/residual_agent.pt --base-policy-type one_demo

IBRL’s --bc-checkpoint must match its frozen deterministic actor (128 -> 64 -> 32, Tanh output), the task’s observation size, and its preprocessing/action convention. Residual RL’s checkpoint base must match the stochastic actor used in task_ResidualRL.py. Supplying a file only verifies existence before connecting; model weights still must match the architecture when loaded.

R²RL evaluation bypasses demonstration action selection and agent updates. Its trainer budget is max_steps * eval_episodes environment steps, so early-ended episodes can affect the actual episode count. The CLI options --eval, --checkpoint, and task overrides are supported by all online entry points; only R²RL has --eval-episodes and --stochastic-evaluation.

Validation

Run the task-selection tests without connecting hardware:

conda activate offline_rl
python -m unittest discover -s tests -v

The tests cover task/data dimensions, environment construction without online CSV reads, CLI overrides, recorded observations, and configuration rejection before robot connections. Actual robot rollouts and physical reset trajectories require validation on the intended fixture.
